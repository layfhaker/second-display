# SecondDisplay — Комплексный чек-лист требований (Checklist)

Данный документ является единым стандартом качества, функциональности и архитектурных требований для всех компонентов системы **SecondDisplay**: всех версий хоста (C#, Rust, Assembly, HolyC), драйвера виртуального дисплея (IddCx) и Android-клиента.

---

## 1. Общие архитектурные принципы

- **Zero Latency (< 16 мс):** задержка между действием на планшете и отображением на экране не должна превышать время одного кадра.
- **100% Языковая чистота (Language Purity):** каждая реализация хоста пишется исключительно на своем целевом языке без посторонних клеевых C++ библиотек или смешанных мостов в исходном коде.
- **Headless & Plug-and-Play:** виртуальный экран работает автономно, включаясь при подключении планшета и выключаясь при его отключении.
- **Production-Ready развертывание:** единый установщик, установка в системный каталог `Program Files`, корректная регистрация в планировщике задач Windows.

---

## 2. Требования к хосту (Host Requirements)

Применяются ко всем 4 реализациям: **`host-c#`**, **`host-rs`**, **`host-asm`**, **`host-holyc`**.

### 2.1. Установщик и развертывание
- [x] **Каталог установки:** строго в `%ProgramFiles%\SecondDisplay` (`{autopf}\SecondDisplay`).
- [x] **Inno Setup:** профессиональный инсталлятор с мультиязычностью (RU/EN), поддержкой тихого режима (`/VERYSILENT /NORESTART`), проверкой разрядности x64.
- [x] **Без видимого терминала (Windowless/Headless GUI):** исполняемые файлы всех хостов компилируются строго с подсистемой Windows GUI (`/SUBSYSTEM:WINDOWS` / `WinExe`). Запуск из проводника, установщика или автозагрузки происходит на 100% бесшумно, без появления окна консоли `conhost.exe`, cmd или PowerShell.
- [x] **Правильный пайплайн установщика:**
  - [x] Скрытное выполнение вспомогательных скриптов (`SW_HIDE` / `runhidden`) без мелькания окон консоли при установке и удалении.
  - [x] Предварительная очистка (`ssInstall`): тихое завершение старых процессов хоста перед распаковкой новых бинарников.
  - [x] Запрет преждевременного запуска: регистрация задачи в Планировщике задач (`Register-HostTask`) не стартует процесс во время установки.
  - [x] Запуск строго на финише: приложение запускается исключительно один раз при нажатии «Завершить» на странице Finish по галочке `[Run] postinstall nowait skipifsilent`.
- [x] **Синглтон (Single Instance):** гарантированная защита от дублирования процессов хоста через именованный мьютекс (`Global\SecondDisplayHost`).
- [x] **Ярлыки:** создание ярлыка в меню «Пуск» и опционально на «Рабочем столе».
- [x] **Комплектность:** инсталлятор включает в себя исполняемый файл хоста, утилиты `adb` (platform-tools), готовый APK клиента, конфигурационные скрипты.
- [x] **Автогранты клиента без тапов по экрану (`seconddisplay-setup.ps1 -PushApk`):**
  - [x] Установка `install -r -g`, затем `pm grant` рантайма (`POST_NOTIFICATIONS`, `READ_MEDIA_*`), `appops set SYSTEM_ALERT_WINDOW allow`.
  - [x] Включение `ShortcutAccessibilityService` через `settings put secure enabled_accessibility_services` + верификация; при блокировке OEM — честный WARNING с путём `Settings > Accessibility > SecondDisplay`.
  - [x] Отдельный детект `unauthorized` (непринят RSA-диалог «Allow USB debugging?») с командой повтора `-PushApk`; `pm grant` без `GRANT_RUNTIME_PERMISSIONS` у shell не используется.
  - [x] Автостарт клиента после установки (`am start -n com.seconddisplay.client/.MainActivity`).
- [x] **Деинсталляция:** чистое удаление всех файлов, удаление запланированных задач Windows, очистка временных логов в `%LOCALAPPDATA%\SecondDisplay`.

### 2.2. Производительность и частота кадров (FPS)
- [x] **Минимальный FPS:** стабильные **30 FPS** при слабом GPU/CPU.
- [x] **Целевой FPS:** **60 FPS** (с возможностью переключения на 90 / 120 FPS при поддержке экраном планшета).
- [x] **Аппаратный энкодер:** использование аппаратного кодирования HEVC (H.265) через Media Foundation MFT (Intel QuickSync, NVIDIA NVENC, AMD AMF) с мгновенным программным фоллбэком.
- [x] **Битрейт:** от 12 до 20 Мбит/с (настраиваемый адаптивный битрейт в зависимости от пропускной способности).
- [x] **Low-Latency режим:**
  - [x] Установка флага `MF_LOW_LATENCY = 1` для MFT кодировщика.
  - [x] Установка сокетного флага `TCP_NODELAY = 1` (отключение алгоритма Нагла) для мгновенной отправки пакетов видео и курсора.
  - [x] Zero-queue буферизация: отбрасывание устаревших кадров при задержке сокета, приоритет самого свежего кадра.

### 2.3. Захват экрана (Screen Capture)
- [x] **Технология:** аппаратный захват через **DXGI Desktop Duplication (`IDXGIOutputDuplication`)**.
- [x] **Отсутствие черного экрана:**
  - [x] Исключение использования GDI `BitBlt` для виртуальных дисплеев (GDI возвращает пустые черные кадры для IddCx).
  - [x] Обязательная привязка потока к интерактивному десктопу Windows (`OpenDesktopA("Default")` + `SetThreadDesktop`) для работы под Task Scheduler, службами и фоновыми процессами.
- [x] **Автоопределение монитора:** автопоиск виртуального дисплея (`\\.\DISPLAY5`, `\\.\DISPLAY6`) или монитора с разрешением 1920x1280.
- [x] **Обработка исключений DXGI:**
  - [x] Корректная обработка `DXGI_ERROR_WAIT_TIMEOUT` (отправка предыдущего кадра без падения FPS).
  - [x] Обработка `DXGI_ERROR_ACCESS_LOST` (мгновенный автоматический перезахват при смене видеорежима или UAC-запросах).

### 2.4. Системный курсор и ввод
- [x] **Аппаратный курсор:**
  - [x] Определение текущей формы курсора через `GetCursorInfo` / `GetIconInfo`.
  - [x] Извлечение реального 32-битного BGRA изображения с субпиксельной альфа-маской (поддержка указателя, стрелки, I-beam, руки, resize-курсоров).
  - [x] Двухпроходный рендеринг (на черную и белую подложку) для идеальной отрисовки черных контуров и прозрачности.
  - [x] Отправка курсора только при изменении позиции или формы (throttling), исключая флуд сокета на статичном экране.
- [x] **Ввод мыши и тача:**
  - [x] Инъекция тач-событий (DOWN, MOVE, UP, Cancel) через `SendInput` (`INPUT_MOUSE` / `MOUSEEVENTF_VIRTUALDESK`).
  - [x] Высокая точность маппинга нормализованных координат планшета (0.0 .. 1.0) в абсолютные координаты виртуального монитора.
- [x] **Ввод клавиатуры:**
  - [x] Инъекция нажатий клавиш через `SendInput` (`INPUT_KEYBOARD`).
  - [x] Поддержка скан-кодов, виртуальных клавиш (VK), модификаторов (Shift, Ctrl, Alt, Win), функциональных клавиш и мультимедийных кнопок.

### 2.5. Языковая чистота реализации
- [x] **`host-c#`:** 100% C# (.NET 8), библиотеки Vortice.Direct3D11 / Vortice.DXGI. Никаких внешних C++ DLL.
- [x] **`host-rs`:** 100% Rust, библиотека `windows-rs`, Tokio. Никаких C++ библиотек.
- [x] **`host-asm`:** 100% MASM x64 (`ml64`), чистые ассемблерные исходники (`.asm`, `.inc`). Прямые вызовы Win32 API и COM vtables.
- [x] **`host-holyc`:** 100% HolyC (`.HC`), автономный транспайлер `holyc.py`. Прямой код на HolyC без сторонних мостов.

### 2.6. Автопереключатель и слежение за подключением планшета
- [x] **ADB & PnP Monitor:**
  - [x] Фоновый поллинг статуса подключенных устройств каждые 1–2 секунды.
  - [x] **adb-link (без спавна `adb.exe` на хот-пате, все 4 хоста):** прямой сокет к adb-серверу `127.0.0.1:5037` с фреймингом `SERVICES.TXT` — `host:devices` для опроса (~2мс вместо ~30–50мс на `CreateProcess`), `host:transport:<serial>` + `shell:`/`reverse:` для `pm list`/`am start`/`reverse`, персистентный `host:track-devices` (Rust/C#) с кэшем-снапшотом; при любой ошибке сокета — тихий fallback на `adb.exe`.
  - [x] Источники: `host-rs/src/adblink.rs`, `host-c#/SecondDisplay.Host/AdbLink.cs`, `host-holyc/src/host.HC` (`AdbLink*`), `host-asm/src/main.asm` (`adb_link_*`).
  - [x] Постоянный `adb server` не убивается хостами (`kill-server` запрещён во время стрима); `unauthorized`/`offline`/`no permissions` скипаются с дебаунс-рестартом сервера только в простое.
  - [x] При обнаружении планшета: автоматическое выполнение `adb reverse tcp:27315 tcp:27315`.
  - [x] Автоматический запуск Android-клиента через `adb shell am start -n com.seconddisplay.client/.MainActivity`.
- [x] **Управление виртуальным экраном:**
  - [x] Включение виртуального дисплея при активном подключении (`pnputil /enable-device`).
  - [x] Мгновенное отключение дисплея при отключении кабеля USB: HolyC — на первом missed poll (0.5с), C#/Rust — 2 missed polls × 1с; `pnputil /disable-device` + обязательный DETACH MTT-фантома (`ChangeDisplaySettingsEx(DETOACH)`), иначе `Disable-PnpDevice` оставляет призрак в топологии.
  - [x] Дебаунс подключения (2 подряд present-polls) против дребезга USB-перечисления; `Status: Error` в PnP ≠ выключен, смотреть на `Screen::AllScreens`/`EnumDisplayDevices`.
  - [x] Автоматическая UAC-самоэлевация (RunAs) для гарантированного доступа к PnP-подсистеме (`Access is denied` без админа — VDD не переключится).

### 2.7. Автоперезагрузчик и Watchdog при лагах
- [x] **Heartbeat & Latency Watchdog:**
  - [x] Контроль времени прохождения кадров (PTS). Если кодировщик или отправка заблокированы более 500 мс — фиксация лага.
  - [x] Если планшет перестал отвечать на сокет или очередь отправки превышает порог — мягкий сброс сессии.
  - [x] Автоматический перезапуск цикла ожидания соединения без аварийного завершения процесса хоста.
- [ ] **Защита от утечек памяти (Memory Watchdog):**
  - [x] Мониторинг памяти — реализован только в `host-rs`: commit (pagefile) через `GetProcessMemoryInfo`, лимит 8000 МБ, лог раз в минуту, выход с кодом 1 → планировщик перезапускает хоста (`host-rs/src/main.rs`, `start_memory_watchdog`).
  - [ ] Мониторинг Working Set с порогом 300 МБ и перезапуском между сессиями — **не реализовано**: в `host-c#`, `host-holyc`, `host-asm` память вообще не читается; в `host-rs` вместо Working Set/300 МБ используется commit/8000 МБ. Аварийный перезапуск при этом покрывается restart-политикой задачи.

## 3. Требования к драйверу виртуального дисплея (IddCx Driver)

- [x] **Архитектура:** драйвер Indirect Display Driver Model (IddCx v1.4+), работающий в пользовательском режиме (UMDFv2).
- [x] **Разрешения экрана:**
  - [x] 1920x1280 @ 60Hz / 120Hz (родное соотношение 3:2 для популярных планшетов).
  - [x] 2000x1200 @ 60Hz (5:3).
  - [x] 2560x1600 @ 60Hz / 120Hz (16:10).
  - [x] 1920x1080 @ 60Hz (16:9 фоллбэк).
- [x] **Headless-режим:** полноценное функционирование без подключенных физических видеовыходов или активных мониторов ПК.
- [x] **Динамическое подключение (Hotplug):** поддержка программного подключения/отключения монитора (`MonitorArrival` / `MonitorDeparture`) без необходимости перезагрузки ОС.
- [x] **Совместимость:** полная поддержка Windows 10 x64 (20H2+) и Windows 11 x64.
- [x] **Установка:** автоматическая установка сертификата и регистрация устройства через `nefcon` / `devcon` без ручных манипуляций пользователя.

## 4. Требования к Android-клиенту

- [x] **Аппаратное декодирование:** использование Android `MediaCodec` в режиме сверхнизкой задержки:
  - [x] Формат: HEVC (H.265 Main Profile).
  - [x] Флаг `KEY_LOW_LATENCY = 1`.
  - [x] Прямой рендеринг в `SurfaceView` в обход промежуточных буферов SurfaceTexture.
- [x] **Задержка отображения:** время от получения сетевого пакета до вывода на экран не более 8–12 мс.
- [x] **Сенсорный ввод:**
  - [x] Опрос тач-скрина на максимальной частоте экрана (60 Гц / 120 Гц / 240 Гц).
  - [x] Поддержка мультитача (до 10 одновременных точек касания).
  - [x] Плавная интерполяция и мгновенная отправка по TCP пакетов типа `0x20`.
- [x] **Аппаратная и экранная клавиатура:**
  - [x] Перехват нажатий клавиш физической клавиатуры планшета (Bluetooth / чехол-клавиатура) и отправка скан-кодов.
  - [x] Поддержка всплывающей экранной клавиатуры при фокусе на полях ввода.
- [x] **Отрисовка курсора:**
  - [x] Наложение аппаратного слоя курсора поверх декодированного видеопотока с субпиксельной точностью.
  - [x] Корректная обработка горячей точки курсора (Hotspot X, Hotspot Y).
- [x] **Автопереподключение:**
  - [x] При обрыве соединения — фоновое повторное подключение каждые 1–2 секунды без зависания интерфейса.
  - [x] Сохранение параметров (IP, порт, выбранное разрешение).
